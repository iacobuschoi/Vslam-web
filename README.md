# VSLAM Web

브라우저에서 동작하는 **단안(monocular) 비주얼 SLAM** 웹앱입니다. 웹페이지를 열면 카메라가 켜지고, 카메라로 방을 비추며 천천히 움직이면 **실시간으로 3D 포인트 맵**이 만들어집니다. 서버는 정적 파일만 제공하면 되고(빌드 불필요), 모든 연산은 사용자의 브라우저 안에서 순수 JavaScript로 수행됩니다.

- 카메라 → 특징점 추적 → 카메라 포즈 추정 → 3D 점 삼각측량 → Three.js로 실시간 렌더링
- **사진 메시**: 키프레임마다 조밀한 대응점을 추가로 매칭·삼각측량하고, 카메라 이미지를 텍스처로 입힌 3D 표면을 실시간으로 쌓아 갑니다(점 보기로 전환 가능)
- 포인트클라우드(색상 포함), 카메라 궤적, 키프레임을 3D로 표시
- 결과를 **GLB**(텍스처 메시, Blender·Windows 3D 뷰어·온라인 glTF 뷰어) 또는 **PLY**(포인트클라우드) 파일로 저장
- 카메라가 없어도 **데모 모드**(가상의 방)로 동작 확인 가능
- 외부 서비스·API 호출 없음. Three.js는 `lib/`에 포함되어 있어 오프라인에서도 동작

## 실행 방법

```bash
# 1) 이 폴더에서 서버 실행 (Node.js 18+)
node server.js            # http://localhost:8080
# 또는 아무 정적 서버:  python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080` 을 열면 카메라 권한을 요청한 뒤 바로 시작합니다.

### 휴대폰(다른 기기)에서 열 때는 HTTPS가 필요합니다

브라우저 보안 정책상 카메라(`getUserMedia`)는 **HTTPS 또는 localhost**에서만 동작합니다. 같은 Wi-Fi의 휴대폰에서 열려면 HTTPS로 서비스하세요.

```bash
# 자체 서명 인증서 생성 (openssl 필요)
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 365 -subj "/CN=vslam-web"
node server.js            # key.pem/cert.pem 이 있으면 자동으로 https://0.0.0.0:8080 으로 실행
```

휴대폰에서 `https://<컴퓨터IP>:8080` 접속 후 인증서 경고를 수락하면 됩니다. 실제 서버(nginx, Caddy, Vercel, GitHub Pages 등)에 올릴 때는 파일들을 그대로 업로드하면 됩니다. Caddy나 호스팅 서비스는 HTTPS를 자동으로 제공합니다.

### URL 옵션

| 파라미터 | 설명 |
|---|---|
| `?demo=1` | 카메라 대신 가상의 방을 스캔하는 데모 모드로 시작 |
| `?autostart=0` | 자동으로 카메라를 켜지 않고 시작 버튼을 표시 |
| `?fov=70` | 카메라 대각 시야각(도) 지정 |
| `?res=640` | 처리 해상도(긴 변 픽셀, 320/480/640) 지정 |
| `?view=points` | 시작 보기 모드: `mesh`(사진 메시, 기본) / `points`(점) / `both` |

## 사용법

1. 페이지를 열면 카메라가 켜지고 상태가 **초기화 중**으로 표시됩니다.
2. 카메라를 **옆으로(좌우/상하로) 10~30cm 천천히 이동**하세요. 제자리 회전만 하면 깊이를 계산할 수 없어 초기화되지 않습니다.
3. 상태가 **추적 중**이 되면 방을 천천히 둘러보세요. 화면에 포인트 맵이 쌓입니다.
4. 3D 화면은 드래그로 회전, 휠/핀치로 확대, 우클릭 드래그/두 손가락으로 이동합니다. `전체` 버튼은 맵 전체가 보이게 맞추고, `따라가기`는 현재 카메라를 따라갑니다.
5. `사진` 버튼으로 사진 메시 / 점 / 둘 다 보기를 전환합니다. `GLB` 버튼은 사진 메시를 GLB 파일로, 설정의 `PLY 저장`은 포인트클라우드를 저장합니다. `리셋`은 맵을 지우고 다시 초기화합니다.
6. 추적이 끊기면(**추적 실패**) 이전에 스캔한 곳을 다시 비추면 자동으로 복구를 시도합니다.

잘 되는 조건: 질감이 풍부한 실내(가구, 책, 포스터), 충분한 조명, 천천히 부드러운 움직임. 잘 안 되는 조건: 흰 벽만 보이는 장면, 어두운 곳, 빠른 회전/흔들림, 움직이는 사람이 화면 대부분을 차지하는 경우.

단안 카메라이므로 맵의 **절대 크기(미터 단위)는 알 수 없습니다.** 초기화 시 장면의 중앙 깊이를 2.0 단위로 정규화합니다. 루프 클로저와 번들 조정은 없어서 오래 스캔하면 드리프트가 누적됩니다.

## 설정(⚙)

- **대각 시야각**: 카메라 내부 파라미터를 시야각 하나로 근사합니다. 스마트폰 후면 카메라는 보통 70~80°, 노트북 웹캠은 60~75° 정도입니다. 값이 크게 틀리면 맵이 휘어 보입니다.
- **처리 해상도**: 480이 기본입니다. 느린 기기에서는 320, 정밀하게 하려면 640.
- **양방향 추적 검증**: 켜면 잘못된 추적점을 더 잘 걸러내지만 연산이 약 2배입니다.
- **추적 실패 시 자동 복구**: BRIEF 디스크립터 매칭으로 이전 맵에 재정렬합니다.
- **사진 메시 만들기**: 끄면 희소 점만 만들어 연산이 가벼워집니다. **텍스처 해상도** 2배는 카메라 모드에서 더 선명한 텍스처를 쓰지만 메모리를 더 씁니다. **유지할 메시 수**를 넘으면 오래된 메시부터 지웁니다.

js/slam-worker.js   Web Worker 진입점

  slam.js           파이프라인 (초기화·추적·키프레임·매핑·재추적)
  fast.js           FAST-9 코너 검출 + 격자 분산
  klt.js            피라미드 Lucas-Kanade 광류 추적 (양방향 검증, 밝기 보정)
  geometry.js       8점 Essential 행렬 / 호모그래피 RANSAC, 분해, 삼각측량, PnP, 포즈 최적화
  brief.js          회전 BRIEF 디스크립터 (재추적용)
  mesh.js           키프레임 사진 메시 (Delaunay 삼각분할 + 깊이 불연속 필터)
  vendor/           delaunator, robust-predicates (vendored)
  image.js          그레이스케일, 피라미드, 그라디언트, 블러

### 알고리즘 개요

1. **특징점**: FAST-9 코너를 격자마다 최대 1개씩 골라 화면 전체에 고르게 분포시킵니다.
2. **추적**: 피라미드 KLT로 프레임 간 특징점을 추적합니다. 역방향 추적 검증과 윈도 밝기 오프셋 보정으로 자동 노출 변화에 견딥니다.
3. **초기화**: 시차가 충분해지면 8점 Essential 행렬과 4점 호모그래피를 RANSAC으로 동시에 추정하고, 분해한 후보 포즈 중 삼각측량 결과(양의 깊이·재투영 오차·시차각)가 가장 좋은 모델을 고릅니다. 평면(벽만 보이는) 장면에서도 초기화가 됩니다.
4. **포즈 추적**: 등속 운동 모델로 예측한 포즈에서 Huber 가중 Gauss-Newton으로 재투영 오차를 최소화합니다. 인라이어가 부족하면 DLT PnP RANSAC으로 복구합니다.
5. **키프레임/매핑**: 추적점 감소·시차·이동량·회전량 기준으로 키프레임을 추가하고, 시차각 1° 이상인 후보 특징점을 두 뷰로 삼각측량합니다. 관측이 늘면 다중 뷰 DLT로 재삼각측량합니다.
6. **재추적**: 추적 실패 시 현재 프레임의 BRIEF 디스크립터를 최근 맵 포인트와 매칭해 PnP RANSAC으로 포즈를 복구합니다.
7. **사진 메시**: 새 키프레임마다 이전 키프레임에서 최대 1500개의 코너를 KLT로 대응시켜 삼각측량(반밀집 매핑)하고, 추적 중인 맵 포인트와 합쳐 2D Delaunay 삼각분할을 만든 뒤 깊이 불연속·경사각·크기 조건으로 삼각형을 걸러 키프레임 이미지를 텍스처로 입힙니다. 키프레임 메시들은 겹쳐 쌓이며 오래된 것부터 정리됩니다.

## 테스트

```bash
npm test                 # 선형대수·기하·추적·합성 방 통합 테스트 (Node 18+)
npm run test:e2e         # 헤드리스 Chromium에서 데모 모드 실행 (Playwright 필요)
npm run test:e2e:camera  # 합성 방 영상을 가짜 카메라로 주입해 실제 카메라 경로(getUserMedia) 검증
```

통합 테스트는 CPU 레이캐스팅으로 렌더링한 가상의 방에서 파이프라인을 돌려, 정답 궤적과의 오차(유사변환 정렬 후 RMSE)와 맵 포인트의 벽면 밀착도를 검증합니다. 카메라 E2E는 `test/make-y4m.mjs`가 만든 Y4M 영상을 Chromium의 `--use-file-for-fake-video-capture`로 재생합니다.

## 브라우저 지원

Chrome/Edge/Safari(iOS 15+)/Firefox 최신 버전. 모듈 워커, WebGL, `getUserMedia`가 필요합니다. iOS Safari에서는 첫 진입 시 카메라 권한 팝업을 허용하세요.
